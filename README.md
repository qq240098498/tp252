# 冷链温控与批次放行台

冷库与冷藏车的温控值班台：录冷库与探头、登批次、盯温度记录、算超限与断链、判放行还是拒收。

## 运行

```
npm install
npm start
```

默认端口 5252（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：冷库与运行中数量、探头数量与已过校准期的探头数、批次总数与各状态条数、温度记录条数与人工记录数、放行与拒收条数、当前满足放行条件的批次数与被挡下的批次数、没有任何温度记录的批次数、库位变更登记条数与其中改变分段判定的次数、最高与平均 MKT、按冷库一行给出探头与批次数（按当前所在库位）。
- **冷库与探头**：冷库台账（编码、名称、类型、位置、库位、状态）与探头台账（编号、所属冷库、位置、状态、校准有效期、记录条数），都带增改删。
- **批次**：批次清单（批次号、品名、规格、件数、当前所在冷库、入库时刻、状态、温度记录条数、最长超限、累计超限、MKT、断链数、变更次数、放行情况），行内展开各库位段统计（每段记录条数、最长/累计超限、断链、MKT、四条判定）、逐条温度记录（带归属库位）、超限段、段内断链与跨段转移缺口、放行判定、变更历史、放行单（注明当时用的是哪一段数据），并提供「放行」「拒收」「登记库位变更」入口。
- **温度记录**：记录清单（批次、归属库位、探头、时刻、温度、来源、登记人、是否超限），支持按批次与探头筛选、单条新增与删除。
- **放行台账**：放行与拒收记录（批次、决定、时刻、经办人、当时的 MKT、最长超限、累计超限、断链数、判定所用数据段与记录条数、依据）。
- **变更历史**：库位 / 设备变更登记清单（批次、从哪个冷库或车厢、到哪个、变更时刻、登记时刻、原因、经办人、批次现状），行内展开变更前后对照：截至变更时刻的边界对照、按登记时全部已有记录的归属对照、整体指标变化，以及变更前已有放行单的冻结说明。

## 口径（页面上的说明与数字都要与本段一致）

1. **温度带**：默认 2 到 8 摄氏度（可在设置里改），低于下限或高于上限都算超限。
2. **超限段**：按时刻顺序逐条判，连续超限的时段算一段，**中间只要有记录回到范围内就断开**；每段的时长按该段相邻记录的实际时刻差累加。
3. **累计超限**：一个批次从入库到当前，所有超限段的时长之和；**跨月不重置**，按批次周期累计。
4. **断链**：相邻两条记录的时刻差超过 `chainGapMinutes`（默认 15 分钟）算一处断链，缺口时长按实际时刻差算。
5. **MKT（平均动力学温度）**：按动力学公式算，写成 `MKT = −Ea / (R × ln((Σ e^(−Ea/(R·T)) ) / n)) − 273.15`（活化能 Ea 取 83144 J/mol、气体常数 R 取 8.314，T 用开尔文，n 为参与计算的记录条数）；**不是把温度取平均**。
6. **放行判定四条**：单次连续超限不超过 `allowExcursionMinutes`（默认 30 分钟）、累计超限不超过 `allowTotalExcursionMinutes`（默认 120 分钟）、全程没有断链、**参与判定的探头都在校准有效期内**。四条同时满足才算满足放行条件；**没有任何温度记录的批次不能放行**。
7. **同一探头同一时刻既有自动记录又有手工更正记录时，以手工记录为准**；停用探头名下的记录不参与判定。
8. **停用与检修中的冷库**：其批次仍然照常记录与判定，但在清单里要标出来。
9. **库位 / 设备变更要登记**：批次从一个冷库或车厢转到另一个，必须登记变更（从哪、到哪、变更时刻、原因、经办人、登记时刻）；不能用批次修改接口直接改所在冷库。每次变更把批次切成若干**库位段**，批次的"当前库位"取时间线最后一段。
10. **记录归属与边界口径**：每条温度记录按其**记录时刻**归属到当时所在的库位段——记录时刻**早于**变更时刻归变更前库位，记录时刻**恰等于**变更时刻归变更后（新库位）。超限段、断链、MKT、四条放行判定按每一段单独统计，页面上给出每段的记录条数、最长/累计超限时长、断链处数；跨变更边界相邻两条记录的间隔不计入任何一段的段内断链，单独列为"转移缺口"。
11. **判定汇总跟着归属变**：登记变更时冻结并展示变更前后的对照——截至变更时刻的边界对照、以及按登记时全部已有记录的归属对照，点名哪些段的记录条数/超限/断链变了、是哪次变更导致的。
12. **过去的放行结论不重新解释**：放行或拒收时冻结当时判定所用的数据段（哪些库位段、截至时刻、参与记录条数）；放行之后再登记变更，放行台账仍标明当时用的是哪一段的数据，不按新归属重算过去的结论（接口保留按任意时刻重放判定的能力，只用于核对，不回写台账）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/rooms | 冷库清单（支持 status、type、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/rooms/:id | 详情（含探头与批次）/ 修改 / 删除 |
| GET / POST | /api/probes | 探头清单（支持 roomId、status）/ 新增 |
| PATCH / DELETE | /api/probes/:id | 修改 / 删除 |
| GET / POST | /api/batches | 批次清单（支持 roomId、status、product）/ 新增 |
| GET / PATCH / DELETE | /api/batches/:id | 详情（含记录及归属库位、各库位段统计、转移缺口、超限段、断链、变更历史、放行单及当时数据段）/ 修改（不能直接改 roomId）/ 删除 |
| GET | /api/batches/:id/release-check | 放行判定；带 `asOf=YYYY-MM-DD HH:mm:ss` 时只用记录时刻 ≤ asOf 的数据重放 |
| GET / POST | /api/batches/:id/changes | 这个批次的变更登记清单 / 登记一次变更，body `{toRoomId, changedAt, reason, operator, remark}`，返回变更前后段级对照 |
| POST | /api/batches/:id/decision | 放行或者拒收，body `{decision, decider, decidedAt, basis, remark}`；单据冻结当时判定的数据段 |
| GET / POST | /api/records | 温度记录（支持 batchId、probeId、source、from、to；返回带归属库位）/ 新增 |
| DELETE | /api/records/:id | 删除一条记录 |
| GET | /api/releases | 放行台账（支持 batchId、decision；返回当时判定所用数据段与记录条数） |
| GET | /api/changes | 变更登记清单（支持 batchId、roomId、affected=1 只看改变分段判定的） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
